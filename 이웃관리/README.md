# 블로그 이웃관리 (댓글·서이추)

목표: 내 주제와 겹치는 블로그에 **읽고 쓴 댓글**을 달고 서로이웃을 맺는다.

## 원칙 — 이거 어기면 계정 날아간다

자동 댓글·자동 서이추는 네이버가 대놓고 잡는 패턴이고, 운영정책 위반이다.
걸리면 글이 아니라 **계정이 저품질**로 간다. 가봄사봄은 체험단 밥줄이고 에디 블로그는 애드포스트 수입이 붙어 있으니,
**도구 하나 만들자고 그 둘을 걸면 안 된다.**

그래서 위험한 단계를 맨 뒤에 둔다.

| 단계 | 하는 일 | 위험 | 상태 |
|---|---|---|---|
| 1 | 대상 수집 (읽기만) | 없음 | ✅ `collect.py` |
| 2 | 댓글·서이추 초안 생성 (올리지 않음) | 없음 | ✅ `draft.py` |
| 3 | 반자동 — 초안 채워놓고 **사람이 클릭** | 낮음 | ✅ `run.py` |
| 4 | 완전 자동 | 있음 | **안 만든다** (3단계로 충분) |

**3단계에서 멈춰도 남는 장사다.** 손으로 하는 것보다 훨씬 빠른데 최종 클릭이 사람이라 패턴 탐지에 안 걸린다.
4단계는 3단계를 2주쯤 돌려보고 결정한다.

덜 걸리는 방법이 곧 더 잘 먹히는 방법이기도 하다 —
글을 실제로 읽고 쓴 댓글이라야 답방이 오고, 주제가 겹치는 블로그라야 이웃이 남는다.

## 1단계 — 대상 수집 (`collect.py`)

네이버에 **아무것도 쓰지 않는다.** 후보 목록만 만든다.

```bash
# 검색 상위 블로그
python3 collect.py --blog hsh-2022 --keywords "부천 맛집,신중동 맛집"

# 내 글에 댓글 단 사람
python3 collect.py --blog hsh-2022 --visitors --posts 15

# 둘 다
python3 collect.py --blog ioiykd8599 --keywords "AI 자동화" --visitors
```

출처 2가지:
- **검색 상위** — 내 주제 키워드로 상위에 뜨는 블로그. 로그인 불필요. 주제가 겹쳐서 이웃이 오래 간다.
- **방문자** — 내 글에 댓글 단 사람. 답방이라 가장 자연스럽고 안전하다.

결과:
- `work/후보_<blog>_<날짜>.csv` — 눈으로 보고 고르는 목록 (출처·근거·순위·최근글·이력)
- `work/ledger.json` — 지금까지 손댄 블로그 전체 기록

### ⚠️ ledger.json은 절대 지우지 말 것

같은 블로그에 두 번 댓글을 달거나 서이추를 두 번 신청하면 **그게 바로 봇 티다.**
이 파일이 그걸 막는 유일한 장치다. 두 계정이 같이 쓴다.

## 실측으로 알아낸 것

- 세션은 체험단 도구 것(`/Users/edi/블로그 체험단/session/`)을 그대로 쓴다. 따로 로그인하지 않는다.
  만료되면 체험단 도구에서 `cheomdan_insert.py --login --blog <id>`.
- 🔴**댓글 API는 막혀 있다** — `apis.naver.com/commentBox/...`는 "서비스 정책에 의해 사용이 제한되었습니다"(code 3300).
  → 로그인 세션 + Playwright로 화면에서 읽는다.
- 🔑**댓글을 보려면 `m.blog.naver.com/CommentList.naver?blogId=&logNo=` 로 열어야 한다.**
  그냥 글 주소로 열면 댓글이 접혀 있어 아무것도 안 잡힌다.
- 🔑**댓글 작성자는 `trackingCode=blog_comment` 링크로 잡는다.** 이게 가장 확실한 신호.
  (`PostList.naver?blogId=vol87&trackingCode=blog_comment` → 작성자는 `vol87`)
- ⚠️`PostTitleListAsync.naver`는 **countPerPage를 크게 줘도 페이지당 5편만** 준다 → 페이지를 넘겨 모은다.
  (홈판 API가 10개씩만 주던 것과 같은 패턴)
- ⚠️같은 응답이 **JSON처럼 생겼지만 제목 이스케이프가 깨져 있어 `json.loads`가 터진다** → 정규식으로 뽑는다.
- 검색 결과는 **다른 가게/다른 주제 글이 섞여 온다** → 상호명·키워드 토큰으로 걸러야 한다.
  (체험단 도구 `lib/naver-blogsearch.ts`와 같은 문제·같은 해법)

## 2단계 — 초안 생성 (`draft.py`)

후보의 **글 본문을 실제로 읽고** 그 내용에 대한 댓글을 만든다. 생성은 `claude -p`.

```bash
python3 draft.py --blog hsh-2022 --limit 12
```

- 끝에 **질문 하나**를 붙인다 — 답글이 오면 그게 교류의 시작이다.
- 기계 검수: 상투어("잘 보고 갑니다"), 내 블로그 홍보, 느낌표 과다, 길이를 자동으로 잡는다.
- ⚠️**글이 하나도 없는 블로그가 섞여 있다**(방문자 중에 흔함). 안 막으면 블로그 홈을 본문으로 읽고
  "아직 첫 글 전이시네요" 같은 초안이 나온다 → `is_post_url()`로 걸러낸다.
- ⚠️`claude` CLI가 간헐적으로 타임아웃난다(12건 중 1건) → 1회 재시도.

## 3단계 — 반자동 실행 (`run.py`)

```bash
python3 run.py --blog hsh-2022            # 오늘치
python3 run.py --blog hsh-2022 --dry      # 입력·신청 없이 화면만 점검
```

★**스크립트는 등록·확인 버튼을 절대 누르지 않는다.** 글을 열고 초안을 채워놓는 데까지만 한다.
최종 클릭은 항상 사람이 한다 — 그래서 기계적 클릭 패턴이 안 생기고, 잘못된 댓글이 나갈 일도 없다.

안전장치:
- **하루 상한 30명**(`DAILY_CAP`). 넘으면 시작조차 안 한다. `work/daily.json`으로 추적.
- ledger 대조 — 이미 댓글/서이추 한 곳은 자동 제외
- 사람마다 **40~120초 랜덤 간격**
- **서로이웃을 안 받는 블로그 감지** → `buddy_blocked`로 기록하고 다신 시도 안 함 (실측: 6곳 중 2곳이 그랬다)
- 연속 3회 실패 → 즉시 중단 (제재 신호일 수 있다)

## 1000명 서이추 — 계산

- 네이버 상한: 서로이웃 신청 하루 **100건**, 이웃 총 **5,000명**. 1000명은 여유 있음.
- **하지만 상한은 안전선이 아니다.** 100건을 꽉 채우는 게 딱 봇 패턴이다.
- 신청한다고 다 되는 게 아니라 **상대가 수락해야** 1명이다.

| 하루 신청 | 수락률 40% | 수락률 60%(댓글 먼저) |
|---|---|---|
| 30건 | 83일 | **56일** |
| 50건 | 50일 | 34일 |

**하루 30건으로 시작 → 2주 무사하면 50건.** 2~3개월이면 1000명이다.

⭐**건수보다 수락률이 지렛대다.** 30건+댓글선행(56일)이 50건+맨몸신청(50일)과 거의 같은데 위험은 절반이다.

## 서이추 UI (실측)

- 폼: `m.blog.naver.com/BuddyAddForm.naver?blogId=XXX` — **직접 접근 가능, 1단계.** 이걸 쓴다.
  - 서로이웃 라디오 `#bothBuddyRadio`(relation=1) / 이웃만 `#buddyRadio`(2) / 확인 `.btn_ok`
  - **라디오가 없거나 disabled면 = 서로이웃을 안 받는 블로그.**
- ⚠️**모바일 폼엔 서이추 메시지 칸이 없다**(그룹 선택만). PC 팝업(`BuddyAdd.naver`)엔 2단계로 있지만
  **직접 URL 접근이 막혀 있어**(ERR_ABORTED) 블로그 페이지에서 클릭해 열어야 한다 → 안 쓴다.
- 📌메시지가 없어도 괜찮다 — **댓글이 인사말 역할**을 한다. 댓글 알림을 받은 사람이 이름을 알아보고 수락하는 게 실제 흐름이다.
